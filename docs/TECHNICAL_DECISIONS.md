# تصمیم‌های فنی پروژه

این سند، تصمیم‌های اصلی فنی و طراحی در پیاده‌سازی داشبورد مدیریت رزرو را توضیح می‌دهد.

## ۱. فناوری‌های استفاده‌شده

### React و TypeScript

از React برای ساخت رابط کاربری مبتنی بر کامپوننت استفاده شده است. TypeScript نیز با فراهم کردن بررسی نوع داده‌ها، به کاهش خطاها و نگهداری‌پذیری بهتر کد کمک می‌کند.

رابط کاربری به کامپوننت‌های قابل استفاده مجدد تقسیم شده است تا بخش‌های مختلف داشبورد مستقل‌تر توسعه داده و نگهداری شوند.

### Vite

Vite به‌عنوان ابزار توسعه و ساخت نسخه نهایی پروژه انتخاب شده است. این ابزار فرایند توسعه را ساده می‌کند و امکان ساخت خروجی بهینه برای محیط Production را فراهم می‌سازد.

### Tailwind CSS

برای پیاده‌سازی استایل‌ها از Tailwind CSS استفاده شده است. این روش به حفظ هماهنگی ظاهری، طراحی واکنش‌گرا و اعمال سریع تغییرات رابط کاربری کمک می‌کند.

### React Multi Date Picker

از کتابخانه `react-multi-date-picker` برای انتخاب تاریخ در فرم ثبت رزرو استفاده شده است تا انتخاب تاریخ با نیازهای رابط فارسی پروژه هماهنگ باشد.

### فونت Vazirmatn

فونت متغیر Vazirmatn برای خوانایی بهتر متون فارسی و ایجاد هماهنگی بصری در رابط کاربری انتخاب شده است.

## ۲. معماری مبتنی بر کامپوننت

رابط کاربری به کامپوننت‌هایی با مسئولیت مشخص تقسیم شده است؛ از جمله کارت‌های آماری، جدول رزروها، فرم ثبت رزرو، اعلان‌های Toast و پنجره جزئیات رزرو.

این ساختار از تکرار غیرضروری کد جلوگیری می‌کند و تغییر یا نگهداری بخش‌های مختلف رابط کاربری را ساده‌تر می‌سازد.

همچنین قابلیت‌های مرتبط با رزروها در ساختاری مبتنی بر ویژگی سازمان‌دهی شده‌اند تا کامپوننت‌ها و منطق مرتبط در کنار یکدیگر قرار بگیرند.

## ۳. مدیریت وضعیت و ذخیره‌سازی اطلاعات

### مدیریت وضعیت با React

وضعیت رزروها با استفاده از قابلیت‌های مدیریت وضعیت React کنترل می‌شود. هنگام ثبت رزرو جدید یا تغییر وضعیت یک رزرو، رابط کاربری و آمار داشبورد متناسب با داده‌های جدید به‌روزرسانی می‌شوند.

### ذخیره‌سازی با localStorage

برای حفظ اطلاعات رزروها پس از بارگذاری مجدد صفحه، از `localStorage` مرورگر استفاده شده است. در نتیجه، اجرای پروژه به سرور یا پایگاه داده نیاز ندارد.

مزیت این تصمیم، ساده‌تر شدن راه‌اندازی و بررسی پروژه است. در مقابل، اطلاعات فقط در مرورگر فعلی ذخیره می‌شوند و میان دستگاه‌ها یا کاربران مختلف همگام‌سازی نمی‌شوند.

## ۴. مدیریت وضعیت رزروها

رزروها از چهار وضعیت پشتیبانی می‌کنند:

- در انتظار تأیید (Pending)
- تأییدشده (Confirmed)
- تکمیل‌شده (Completed)
- لغوشده (Cancelled)

با تغییر وضعیت هر رزرو، اطلاعات مربوط به آن به‌روزرسانی می‌شود. همچنین اعلان‌های Toast برای نمایش نتیجه عملیات و خطاهای مرتبط استفاده می‌شوند.

## ۵. جست‌وجو، فیلتر، مرتب‌سازی و آمار

قابلیت‌های جست‌وجو، فیلتر و مرتب‌سازی به کاربر کمک می‌کنند رزروهای موردنظر را سریع‌تر پیدا و سازمان‌دهی کند.

کارت‌های آماری نیز اطلاعات خلاصه‌ای از وضعیت رزروها ارائه می‌دهند تا بررسی وضعیت کلی داشبورد آسان‌تر باشد.

## ۶. طراحی واکنش‌گرا

رابط کاربری برای نمایش در اندازه‌های مختلف صفحه، شامل دسکتاپ، تبلت و موبایل، طراحی شده است.

در نسخه دسکتاپ و تبلت اطلاعات رزروها در قالب جدول نمایش داده می‌شوند؛ درحالی‌که در صفحه‌های کوچک‌تر از نمایش کارتی استفاده می‌شود تا اطلاعات بدون نیاز به فضای افقی زیاد قابل مشاهده باشند.

## ۷. بازخورد کاربر و مدیریت خطا

از اعلان‌های Toast برای نمایش نتیجه عملیات و خطاهای مرتبط استفاده شده است؛ بدون اینکه برای هر پیام به صفحه جداگانه‌ای نیاز باشد.

لایه نمایش اعلان‌ها در بالاتر از پنجره جزئیات رزرو قرار گرفته است تا هنگام تغییر وضعیت رزرو از داخل این پنجره، پیام نتیجه عملیات قابل مشاهده باقی بماند.

## ۸. تعامل با صفحه‌کلید و مدیریت فوکوس

برای پشتیبانی از تعامل با صفحه‌کلید، رفتارهای زیر در پروژه در نظر گرفته شده‌اند:

- کلید `+` فرم ثبت رزرو جدید را باز می‌کند، مشروط بر اینکه شرایط اجرای میانبر برقرار باشد.
- کلید `Escape` فرم ثبت رزرو جدید را می‌بندد.
- پس از بسته شدن فرم ثبت رزرو جدید، چه با کلید Escape، چه با دکمه بستن (×)، چه با دکمه انصراف و چه پس از ثبت رزرو، فوکوس به دکمه «ثبت رزرو جدید» بازمی‌گردد.
- کلید `Tab` برای حرکت میان عناصر قابل فوکوس، مانند فیلدها و دکمه‌ها، قابل استفاده است.

میانبر صفحه‌کلید به‌گونه‌ای در نظر گرفته شده است که هنگام تایپ در فیلدهای ورودی مرتبط، به‌صورت ناخواسته اجرا نشود.

## ۹. پشتیبانی از زبان فارسی و چیدمان راست‌چین

رابط کاربری با چیدمان راست‌چین (RTL) و فونت مناسب فارسی طراحی شده است تا نمایش متن‌ها، فرم‌ها و بخش‌های مختلف داشبورد با زبان رابط کاربری هماهنگ باشد.

## ۱۰. ساخت نسخه نهایی و کیفیت کد

TypeScript و ESLint برای بررسی کد و شناسایی مشکلات احتمالی در زمان توسعه استفاده می‌شوند.

فرایند ساخت نسخه نهایی، ابتدا بررسی‌های TypeScript را اجرا می‌کند و سپس خروجی Production را با Vite می‌سازد.

دستورهای اصلی پروژه عبارت‌اند از:

```bash
npm run dev
npm run lint
npm run build
npm run preview
```
